# 个人时区保存失败后的恢复

## 用户场景

同一个正常登录用户通过账户菜单打开设置，个人时区正常从当前浏览器读取。选择东京时，如果浏览器存储暂时无法写入，界面应诚实说明失败，并保持可操作的恢复路径。

## 交互约定

- 正常修改仍即时保存，不需要提交工作区设置
- 写入失败后，时区选择回到本次页面最后一次成功保存的值；不是继续显示未保存的东京
- 选择框附近显示中、英、日三语失败提示，并说明重新选择时区即可重试；提示用 alert 及 aria-describedby 关联选择框
- 失败期间隐藏语言区的自动保存承诺；回滚只恢复界面，不自动重写存储或清除失败提示
- 写入恢复后，用户在同一个选择框重新选择东京，只有真实写入成功才清除失败提示；关闭设置并通过账户菜单重新打开，仍显示东京
- 未重试就关闭不会保存失败的选择，重新打开显示原有持久值
- 持续失败期间可以继续重选，每次失败均回到上次成功值，不产生回滚写循环或未处理的产品事件异常

## 实现与边界

只在 SettingsPage 时区 watcher 中处理目标写入，使用本页最后成功值回滚，不改变 locale.ts、四个时区映射、正常挂载写入或语言/主题行为。初始读取、挂载前存储故障及其他标签页同时修改不是本次修复的验收范围。

正式 SettingsPage.timezoneRecovery.test.ts 有 12 项 DOM 回归，覆盖三语反馈与重选重挂、单次失败不自动重写、持续失败、最新成功值回滚、未重试关闭、其他偏好保持及正常成功对照。测试使用真实 Vue/Pinia/组件/内存路由与合成接口，只在成功挂载后让当前 jsdom 的时区 key 写入失败；不读取会话数据或改变真实用户设置。

这些是 DOM、受控存储和内存路由证据，不代替真实浏览器视觉、实际存储、后端或权限验证。
