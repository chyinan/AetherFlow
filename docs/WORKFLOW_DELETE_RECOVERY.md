# 项目页工作流删除恢复

## 用户契约

点击删除后仍需原有确认。取消不改变行、选择或网络状态；确认后按工作流 ID 禁止重复提交，显示目标名称与等待状态。另一独立工作流可继续由用户确认删除。同一 store 的页面离开、重入不会解除在途目标的互斥。

DELETE 失败保留列表及本地项目链接，显示目标明确的结果未确认说明。失败不代表服务端一定没有删除；用户应先核对列表，再点击删除并确认重试。不会自动重发 DELETE。取消重试保留原提示；确认重试时清除该目标旧提示，其他行的成功不能清除它。离页后的失败也由原操作接住，不导航、不接管新草稿。

成功只移除目标，清理对应本地项目链接，并按同一项目快照嵌入列表中实际移除的唯一 ID 同步已知项目计数。部分列表仍保留其余服务端计数，不把空数组一概视为完整列表，也不重写运行、文件等其他指标语义。重复的成功调用在目标已不在项目嵌入列表时不能再次扣计数。项目与工作流两支 GET 可以采样于不同时间：旧 summary 不能证明新项目计数仍含已删除目标。若项目嵌入列表为空／未知而只有 summary 显示目标，仍过滤目标行，但保留项目原计数；此时不能宣称该未知计数已精确协调。

## 读取窗口

项目页缓存重入会自动读取项目和工作流联合列表。读取尚未全部完成时确认的删除，只在本次读取窗口登记目标；联合快照提交时过滤这些已确认 ID，同时协调嵌入行与计数。其他工作流的新名称、项目数据及部分读取警告仍保留。被新请求取代的旧读取不能提交；完成或失败后清理该请求记录。

删除确认后才开始的新读取仍以服务端为准，可以重新显示同 ID 记录。没有永久 tombstone、全局丢弃读取、自动恢复、后端幂等或跨标签页协调。

## 与重命名恢复的合并协作

删除成功才推进同一目标的 `workflowRenameRequestIds` 代次，失败不推进，其他目标不受影响。该状态与已交付的 PR50 同名、同位置，自动合并后复用 PR50 的现有 `isCurrent()`，阻止旧重命名回执或失败恢复分支把已删除行补回。独立维护基线中该 map 只为合并／组合后的重命名协调预留，不代表本补丁独立修复了整个重命名流程，也未带入 PR50 的重命名实现。删除后的新操作可以使用新的代次，未引入永久 ID 屏蔽。

## 验证范围

回归使用真实 Vue、Pinia、Vue Router memory history、ProjectsPage、projectStore、projectApi 与 workflowApi，HTTP 最底层传输由测试内存 fixture 替换，系统确认框由 stub 替换。覆盖确认／取消、等待互斥、不同目标并行、失败归属及显式重试、成功计数、晚到联合读取两顺序、部分读取失败、较新请求、离页重入、后续服务端权威与中英日文案。

这是确定性 jsdom 前端派发及状态协调证据，不证明真实浏览器布局、原生确认框、真实后端 DELETE/404/幂等行为、Provider、部署或跨端 E2E。没有真实删除用户工作流。
