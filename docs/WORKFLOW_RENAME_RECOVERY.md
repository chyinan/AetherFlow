# 工作流重命名等待与恢复

## 用户路径

在项目页选择工作流的“重命名工作流”，填写名称并保存。读取定义和提交保存都属于同一次等待：名称输入和保存按钮暂时禁用，同一弹框重复提交只派发一次重命名请求。空白名称不提交。

等待期间两处关闭按钮仍可使用，也可以离开页面。提示会说明关闭窗口不能取消已提交请求。关闭、重新打开或卸载使旧弹框代次失效，旧成功、失败和 finally 不会关闭新草稿、写入新错误、解除新请求的等待锁或抢走项目选择。关闭后明确提交新草稿属于新的用户操作，可以与旧请求并行。

当前定义读取或保存请求失败时保留输入，恢复按钮并显示“未能确认重命名结果”的提示。客户端不能仅凭网络失败断言服务端未保存；用户应核对工作流列表后再显式重试。没有自动保存重试或删除补偿。

## 保存确认与列表回读

保存接口已成功返回后，先把已确认名称写入现有工作流摘要和项目嵌入列表。随后列表回读只是独立的刷新阶段；它失败不会让重命名 action reject，当前保存弹框正常关闭，已保存名称仍可见。

项目或工作流列表错误沿用页面列表提示与重试入口。列表重试只重新读取，不会再发送重命名 PUT。工作流列表单独失败而摘要被清空时，仅从当前目标项目响应的嵌入工作流恢复已给出的兄弟，并补回本次确认条目；按 ID 去重，兄弟名称与状态原样保留，目标项目已移除则不恢复。该恢复受本次列表请求归属约束，不覆盖较新的读取。后续正常读取继续以服务端列表为准。

局部恢复优先保留保存结果或原摘要已有的后端项目 ID，不推断或强转项目 ID。若两者均未提供，则使用既有便利关联 helper，补齐本次目标项目响应明确给出的兄弟 ID；不改其他项目的关联。这些关联仍只用于从当前工作流摘要中查找，不永久合并已被后续正常列表移除的条目。

同一工作流的不同重命名请求按发起代次区分。较新的操作发起后，旧保存回执仍向其调用者返回已保存记录，但不覆盖当前名称或发起旧列表刷新。此规则防止“服务端先写 A 后写 B，仅 A 的回执迟到”把已确认的 B 回滚为 A；它不依赖服务端版本假设，也不承诺改变服务端并发写入顺序。

定义读取完成后也会检查该操作归属。若读取等待期间已发起同一工作流的新重命名，旧调用只返回已读定义供失效页面操作收尾，不再派发尚未提交的 PUT；这与已经派发的 PUT 无法撤销不同。

没有变更工作流新建的项目 ID／名称导航、项目创建的代次与选择规则、删除操作、后端、依赖、权限或用户设置。名称之外的定义内容继续通过既有读取与保存接口处理；本次不引入版本合并或跨弹框全局锁。

## 验证边界

正式回归使用真实 Vue、Pinia、Vue Router memory history、ProjectsPage、projectStore、projectApi、workflowApi 及 API 映射，只在 HTTP 和旁支 store 边界使用受控替身。覆盖正常成功、名称裁剪、空名、重复提交、读取／保存失败与显式重试、顶部／底部关闭、旧成功／失败与新请求交错、卸载重入、项目选择、保存成功后完整／部分列表失败及中英日提示。

这些测试证明 DOM、路由、状态和前端请求顺序，不代表实际浏览器视觉、原生历史导航、真实后端或数据库、Provider、Java 全量、部署或真实性能容量。未在生产环境发送重命名请求。
