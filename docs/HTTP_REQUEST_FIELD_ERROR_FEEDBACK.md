# HTTP 请求配置字段错误反馈

本轮只补充纯 props `HttpRequestConfigPanel` 中已有请求体错误的字段关联。适用于用户输入冲突请求体、GET/HEAD 保留请求体或固定 JSON 语法错误之后，返回具体字段纠正配置的场景。

## 保持的校验契约

校验继续基于父级传入的配置，使用原有 trim、默认 GET、JSON.parse、判断顺序和错误文案：

1. 固定 JSON 与请求体变量同时非空时，优先显示互斥提示，仅标记两个来源
2. GET/HEAD 带请求体时，标记方法和实际非空的来源
3. 可带请求体方法的 JSON 解析失败时，仅标记 JSON 字段
4. 空白、正常或纠正后的配置不保留错误状态与描述引用

有效 JSON 仍可为对象、数组或标量。URL、URL 变量、错误策略与输出变量不参与这些请求体错误。此改动不增加 URL、业务或安全校验，也不改变后端校验、保存或运行门禁。

## 呈现与事件

已有提示保留 role=alert。提示使用 Vue useId 生成的稳定 ID，同一 app 的多个面板各自唯一。当前相关字段设置 aria-invalid=true，并使用 aria-describedby 指向存在的当前提示。错误原因改变时，旧字段的状态与引用随 props 更新清理；正常后提示与相关属性一并移除。

原控件不重新挂载、不自动聚焦或移动焦点。输入仍只发送原始字符串 update 事件，重复输入不被吞掉或转换。父级没有回传 props 前，面板继续使用原配置校验，不表示配置已保存。

## 验证与边界

只运行经独立全文审核的 `HttpRequestConfigPanel.feedback.test.ts` 新单文件白名单。测试只挂载纯 props 面板和 Vue 宿主，使用合成输入与 DOM focus，禁止 fetch、XMLHttpRequest、WebSocket、EventSource；没有 NodeInspector、真实 store、图、身份、文件、配置持久化或真实网络流程。

固定用例覆盖既有错误提示与字段缺失关联的原行为反例、冲突优先、GET/HEAD 与默认方法、JSON 语法、错误切换、正常恢复、合法 JSON 各类型、原始重复 emit、父 props 未回写、同 app 两实例唯一 ID、原 DOM 与当前焦点保持。多项用例是同一呈现问题的状态覆盖，不代表发现多个独立 Bug。
