# 运行历史的工作流定义 ID 精确筛选

## 场景

定义 A 的 ID 是 1、定义 B 的 ID 是 2，先运行 B 得到运行实例 1。此时按工作流 ID 1 筛选
历史，查询条件是"定义 ID 等于 1 或 运行实例 ID 等于 1"，于是 B 的运行被当成 A 的运行
返回；分页总数同样被污染。

## 契约

- 新增 `definitionId` 查询参数：精确匹配工作流定义 ID，不再顺带匹配同号的运行实例
- `definitionId` 与 `workflowId` 同时出现时以 `definitionId` 为准
- 计数、列表与分页使用同一筛选条件，总数与条目口径一致
- 旧 `workflowId` 参数的兼容行为保留：仍按"定义 ID 或运行实例 ID"匹配
- 运行 ID 入口保留：按运行 ID 打开详情的既有路径不变
- 前端历史筛选：数字工作流 ID 使用 `definitionId`；非数字取值沿用旧参数
- 编辑器按工作流定向读取最近运行时，已知定义 ID 时使用精确筛选
- 本项不是权限问题，用户可见范围不变

## 验证范围

- 服务端：定义 ID 筛选的 SQL 条件只含 `definition_id`，计数与列表条件一致；旧参数仍
  含 `OR id`；非法的定义 ID 返回 400
- 接口：控制器透传 `definitionId`，OpenAPI 参数文档同步
- 前端：数字工作流筛选发送 `definitionId`；非数字工作流筛选仍发送 `workflowId`；
  编辑器定向读取按定义 ID 精确查询
