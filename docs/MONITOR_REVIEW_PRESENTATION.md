# 监控待复核事件的选择与状态呈现

## 范围、场景与证据

本轮基于维护分支 `ed347e543cb918ab22d0c20f3c86cc426b01808f`，只处理 `/monitor` 的“发现待复核事件 → 选择事件 → 核对 Trace”流程。它承接 [前端逐页任务层级检查](FRONTEND_PAGE_HIERARCHY_REVIEW.md) 中记录的 click-only 复核入口。已合并的刷新选择连续性修复继续保留；本轮与服务商检查页修改独立。

用户希望用键盘检查复核队列中的第二个事件，随后核对实际应用、原因和 Trace。基线存在两处有直接证据的断点：

1. 队列条目是只有 click 处理器的 `article`，没有原生按钮、默认顺序焦点或键盘激活语义。通过原有“人工复核”标题和事件内容定位的基线反例，实际收到 `tabIndex=-1`，不是预期的原生按钮默认值 0。
2. 初次日志仍在等待时，队列未区分“未知”与“成功空”。不依赖新增测试标识的基线反例实际收到“人工复核0待复核…暂无结果”。日志读取失败同样不能证明没有待办。

这些反例验证了 DOM 语义和错误的状态结论，不是浏览器实测 Tab 路径、Enter/Space 默认激活或像素复现。其余新结构验收失败不应计为额外独立业务缺陷。

## 修复后的交互契约

- 复核条目使用 `button type="button"`，保持整行、左对齐和明确的 `focus-visible` 样式。应用、复核原因、状态、来源、渠道和延迟继续完整存在于 DOM，没有新增提交动作
- 事件流与复核队列都根据实际选中事件设置 `aria-pressed`，通过 `aria-controls` 指向同一个 Trace 区域。队列还显示“已选中”，避免只靠颜色判断
- Trace 使用真实二级标题，具名描述包含实际应用及完整 Trace ID；没有把既有概括状态作为新无障碍名称的依据
- 普通选择、重复选择、往返选择只沿用本地选择逻辑，不新增焦点转移、滚动、路由或接口读取
- 提示明确说明：选择事件用于查看追踪详情，查看不会提交人工复核。这里没有新增审批或完成复核功能

仅修改页面模板与局部中英日文案。脚本部分、请求参数、API、身份监听、权限门禁、请求代次和既有刷新/选择生命周期均未改动。全局治理卡与原有告警继续保留，不借此展开图、文件或身份功能审查。

## 未知、空与刷新恢复

复核队列是否可信只由事件日志的 `conversationsAvailable` 决定，不能因为独立指标读取失败就否定已成功获取的事件列表。

| 状态 | 队列呈现与恢复方式 |
| --- | --- |
| 初次获取日志中，无旧快照 | 数量待确认、局部加载提示及 `aria-busy=true`，不显示零或无结果 |
| 初次日志读取失败 | 数量待确认与局部不可用说明；使用既有顶栏“刷新平台状态”重试 |
| 日志成功且为空 | 确认零待复核，显示明确空提示；没有 Trace 详情 |
| 有普通事件、没有待复核事件 | 确认零待复核，普通事件和其 Trace 仍然可检查 |
| 指标读取失败、日志成功 | 队列数量及内容仍可信，保留独立的整体遥测警示 |
| 有旧队列或旧零快照，刷新等待中 | 保留旧数量和可选择项，同时说明正在刷新、暂显上次结果；标记忙碌 |
| 刷新期间改选另一事件 | 沿用已合并的选择连续性行为，回执不覆盖仍存在的新选择 |
| 日志刷新失败 | 沿用既有清空行为，局部改为未知而非成功空；通过原顶栏刷新恢复列表 |

没有待提交表单或模态，因此取消就是改选或离开页面，不额外增加确认步骤。恢复测试只控制内存中的读取替身，不验证真实网络、鉴权或服务端故障恢复。

## 验证与边界

唯一测试白名单为 `frontend/src/pages/monitor/MonitorPage.reviewPresentation.test.ts` 中经全文及逐项审阅的 15 项用例。固定一个静态管理界面，不初始化真实身份 store 或 Pinia；治理模块完整 mock，仅返回空来源/空资源；服务 API 只允许两个内存读取替身。API client、fetch、XMLHttpRequest、WebSocket、EventSource 和其他业务动作均禁止调用。所有 pending 夹具均在清理时释放。

覆盖原生按钮/默认 tabIndex/焦点样式源码契约、初读假空反例、双列表选择与具名 Trace、重复选择及程序化焦点、普通事件、长原因与完整 ID、日志失败/空、指标失败的独立性、旧队列与旧零刷新、失败后显式重试及中英日文案。

基线 15 项失败，其中前两项是上述精确反例，其他 13 项主要因新结构尚不存在而失败。实现后同一冻结测试文件最终 15 项全部通过，独立审查也重新执行这 15 项并全部通过（2026-10-17 18:11 UTC）。独立源码复核确认没有剩余源码/受控 DOM 阻断，页面脚本逐字未变。

应用与构建配置的 `vue-tsc` 类型检查均退出 0；Vite 生产构建退出 0。构建仍有既有的大于 500kB 分块提示，最大工作流页约 565.08kB，不据此声称性能验收完成。
