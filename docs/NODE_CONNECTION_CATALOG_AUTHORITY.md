# 连接目录的局部结果与权威刷新

## 场景

A 标签页保存连接后，本地结果被永久保留并压过后端目录。B 标签页随后修改同一连接，A
标签页成功刷新仍显示旧配置，而后端探测用的是新配置：界面与实际行为不一致，用户之后
测试成功并保存旧表单还可能把更新回退。

## 契约

- 保存前发起的旧读取不能盖掉刚保存的结果：读取期间保存的本地结果继续保留
- 保存之后发起的读取是权威的：服务端已列出该连接时，以后端目录为准，本地结果不再覆盖
- 服务端尚未列出该连接时（新建后尚未同步、旧读取缺项），本地结果继续保留
- 局部结果只用于展示，不写回服务端；刷新本身不产生任何写入
- 目录是否完整仍由 `ready` 反映，读取失败保留错误并允许真正的列表重试
- 写请求去重与保存反馈保持不变

## 验证范围

前端 store 测试覆盖：保存后发起的权威 GET 能刷新连接、保存前发起的旧 GET 不盖掉新保存、
服务端尚未包含时保留本地结果、重复回执去重、目录读取失败后重试补齐。
