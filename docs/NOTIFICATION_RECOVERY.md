# 通知中心结果与恢复

## 有界契约

通知历史读取、全部已读和清空分别有可见的等待与失败状态。只有通知 API 确认写入成功，前端才应用对应的本地结果；明确拒绝时保留原列表和未读状态。写失败提供原动作的显式重试入口，历史失败提供独立的重新读取入口。没有自动重试写入。

同一集合的全部已读与清空共享等待互斥：按钮禁用，store 同样拒绝重复或交叉派发。写入等待时不发新的历史读取。写开始即作废已经发出的历史读取，忽略其成功、失败和结束回执；普通读取只允许最后发出的那一次改变列表、错误和加载状态。写完成后的新读取仍以后端历史为准，不使用永久墓碑，也不把旧记录永久隐藏。

本地成功变换只覆盖操作起始已有的通知项。写等待期间新增或被新状态替换的实时项保留在本地，避免迟到 ACK 抹掉新消息或把新事件标成已读。通知 API 仍执行原有服务端全量操作，没有新增时间参数，也没有改变服务端筛选范围。客户端不能推断服务端实际提交时刻；后续明确读取仍按权威后端快照协调。该规则不承诺请求发出之后的任何服务端消息都不在服务端全量操作范围内。

通知缓存写入为尽力而为；缓存不可用不把已确认成功的服务端操作改报为失败。刷新失败保留原来已经显示的消息。首次无缓存的等待或读取失败不显示“暂无消息”；只有没有等待和错误的空列表显示空状态。

## 回归层次

`frontend/src/components/layout/TopStatusBar.notificationRecovery.test.ts` 使用真实 Vue 顶栏、Teleport、Pinia、i18n 与历史合并器，覆盖正常成功、空历史、明确拒绝、当前面板重试、重复及交叉点击、旧读取、新实时项与迟到回执、后续权威读取和缓存不可用。通知 API 模块完全替换为内存函数；实时订阅也完全替换为无网络回调。每项仅初始化一个普通 USER，不切换身份。

这些回归是 jsdom 下的有界前端证据，不是真实 HTTP、后端事务、实时流令牌、身份权限、视觉几何、部署或真实 E2E 验收。没有在此处新增或变更通知流、用户标识、令牌、权限或后端接口。
