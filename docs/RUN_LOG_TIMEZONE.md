# 运行日志和历史时间戳时区展示

运行日志的 `time` 保留原有兼容显示，新增可选的 `occurredAt` 保存原始时刻。HTTP 历史日志和运行时事件透传来源值；正常本地创建的运行提示、恢复失败和连接提示使用同一个 `Date` 生成原始 ISO 时间及兼容显示。

`LogStream` 在渲染时，使用应用当前语言和已保存的时区格式化有效的原始时刻。因此从设置路由返回、显式刷新或重新挂载时，即使继续复用同一运行的缓存日志，也能显示当前时区。原始时刻、缓存中的 `time`、日志正文及顺序均不因展示而改写，刷新期间的实时日志合并优先级保持不变。

没有原始时刻的旧日志、静态演示日志和无效日期沿用原有 `time`，不能从时分秒字符串推断原始时间。本次不增加其他标签页 `storage` 事件的即时响应，也不改变运行控制或实时连接行为。

回归覆盖三种语言下的 UTC、东京、上海及设备时区展示，原始来源不变，旧值回退，本地日志创建，以及同 ID 的实时日志在 HTTP 刷新期间继续优先。组件和通道接线测试使用 jsdom 与受控接口，不代表真实浏览器、原生历史导航、实际实时连接、后端或 Provider 验证。

## 运行历史开始时间

运行历史 API 的 `startedAt` / `updatedAt` 来自 Java `LocalDateTime`，没有携带时区偏移。只有提供合法的 `VITE_SERVER_TIMEZONE_OFFSET` 时，前端才用该偏移解释此类服务器时间，再按应用保存的时区格式化；未配置时保留原有浏览器本地解析。显式 `Z` / `±HH:MM` 时间和仅日期值沿用原有解析语义。标准 Docker Java 镜像设置 `TZ=Asia/Shanghai`，因此 Docker 的默认 `+08:00` 匹配该部署。

此变量是固定数值偏移，不是 IANA 时区，不能表达夏令时。运行本地 Vite 时可在环境变量或 `frontend/.env.local` 中设置，示例见 `frontend/.env.example`。Docker Compose 将根 `.env` 中的值作为两个前端构建目标的 build-arg 传入；自定义部署应让该偏移与 workflow-service 的 JVM 时区一致。数据库中的历史 `DATETIME` 不保存时区，部署应保持后端时区稳定；更改服务器时区后，旧行无法仅凭现有值还原为唯一时刻，跨时区迁移需要另行定义并持久化时区/偏移契约。
