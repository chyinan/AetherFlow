# 工作流运行重试次数展示

## 修复范围

运行时间线原先在刚启动的节点上固定保留 `retryCount: 0`，实时重试事件没有映射该字段；冷重开运行时，事件恢复也没有保留已发生的重试次数。

现在只从后端 `NODE_RETRYING` 事件的正整数 `attributes.attempt` 读取次数。当前后端从 1 开始递增，在安排对应重试、进入退避等待前发布这个序号。它表示已安排的自动重试次数，不表示人工“失败节点重跑”次数。

- 实时事件与 HTTP 节点摘要使用同一映射
- 同一运行、同一节点的重复/旧回放保留最大已知次数，不重复累加
- 后续完成、失败或没有序号的事件不会擦除已知次数
- 同运行恢复期间收到较新节点事件，或已完成节点遇到较旧历史时，只补充已证实的次数，仍保留较新的状态与输出
- 冷重开运行通过事件历史恢复次数；历史没有有效重试证据时保持未知，不猜测为零
- 普通节点业务输出中的 `attempt` 或 `retryCount` 不作为重试元数据
- 历史接口只提供有限事件时，只能显示实际取得的证据；不保证恢复被服务端裁剪的记录

没有修改运行策略、重试次数上限、退避、幂等、服务端执行、人工重跑或取消逻辑；没有新增自动重试。

## 验证

回归使用真实 Vue、Pinia、运行页面、API 映射与 SSE 解码，HTTP 和流传输受控。覆盖新启动运行、冷重开完成运行、重复/较旧回放、HTTP 摘要、恢复失败、多节点、失败终态与无效/业务字段边界。

这是前端展示与恢复测试，不代表真实浏览器、网络时序、后端重试执行、Provider、部署或容量验收。
