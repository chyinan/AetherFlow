# Workflow 页面加载恢复

## 工作流与项目目录是两类读取

打开已有工作流时，页面同时读取工作流定义和项目目录。工作流定义决定画布能否打开；项目目录用于工作台选择与列表展示，失败不代表工作流定义读取失败。

- 工作流 GET 失败：立即显示阻断提示、“重新加载”和“返回项目”，不等待节点目录、运行列表等辅助读取。重试仍只针对当前工作流定义，成功后照常恢复该工作流的运行状态和编辑器。等待时原地显示加载、保留“返回项目”，同一个重试按钮保持焦点并阻止重复提交。再次失败显示新错误，成功打开时只有仍持有原按钮焦点才将其移到工作流标题。用户已移走焦点或离开时不抢回。重试时不新增等待运行恢复的条件。
- 首次打开仍等待已有的辅助资源；如果等待时切换工作流，编辑器由当前地址的加载决定，不等上一份定义先返回。旧读取也不能在辅助资源就绪后补做页面订阅。离开编辑器后，迟到的定义或错误不能覆盖共享画布状态（例如让侧边栏从最后成功打开的工作流跳到未打开的工作流）。
- 项目目录失败：保留已加载的画布，在编辑器标题区显示单独的项目列表提示和重试操作；重试只重新读取项目目录。
- 没有路由 `projectId` 时，先保留工作流详情明确返回的 `projectId`。详情没有该字段时，目录成功后才调用现有 `selectProjectByWorkflow` 关联查找；不自行推断项目 owner。

## 保留当前编辑

画布撤销和重做快捷键只作用于可见编辑器。切换到另一份工作流的定义加载、失败或重试期间，即使仍保留上一份已保存工作流的本地历史，快捷键也不会修改那份画布或让返回项目误弹「未保存」确认。恢复到可见编辑器后，快捷键仍可正常撤销、重做和保存。

项目列表重试不重载工作流定义、不重置画布，也不改变当前工作流的 `projectId`。节点、连线、撤销历史和未保存编辑保持原样。重试期间提示和按钮保留，按钮显示进行中状态并禁用；重复点击会复用当前读取。已卸载页面的迟到结果不会写入页面反馈。项目 store 自身继续用读取代次丢弃较旧的列表响应。

路由上的 `projectId` 解析、现有工作流归属选择和服务端鉴权保持原路径。项目列表不可用不改变服务端授权结果，也不推断工作流 owner。

## 验证边界

`workflowLoadErrorOwnership.test.ts` 使用真实 Vue 页面和 Pinia 工作流/项目 store，通过受控 API 响应覆盖两个请求的成功、失败、重试以及路由切换与卸载交错，也验证辅助读取未结束时已有明确信息的失败不会被加载状态盖住、重试等待期间可返回、焦点连续且不会被迟到回执抢回，以及 A 的旧定义未返回时仍能打开 B。该回归验证前端请求和 DOM 状态，不代表真实后端、身份授权或真实浏览器视觉验收。

`workflowHiddenCanvasShortcuts.test.ts` 在 jsdom 挂载真实编辑页和节点检查器，通过受控 Axios 响应实际提交一份编辑、切换到下一份定义并覆盖加载、失败、重试和返回项目，再核对撤销/重做后的保存读回。不代表真实浏览器或部署后端验收。
