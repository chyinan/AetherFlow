# Workflow 页面加载恢复

## 工作流与项目目录是两类读取

打开已有工作流时，页面同时读取工作流定义和项目目录。工作流定义决定画布能否打开；项目目录用于工作台选择与列表展示，失败不代表工作流定义读取失败。

- 工作流 GET 失败：保留现有阻断提示和“重新加载”操作；重试只重新读取当前工作流。
- 项目目录失败：保留已加载的画布，在编辑器标题区显示单独的项目列表提示和重试操作；重试只重新读取项目目录。
- 没有路由 `projectId` 时，先保留工作流详情明确返回的 `projectId`。详情没有该字段时，目录成功后才调用现有 `selectProjectByWorkflow` 关联查找；不自行推断项目 owner。

## 保留当前编辑

项目列表重试不重载工作流定义、不重置画布，也不改变当前工作流的 `projectId`。节点、连线、撤销历史和未保存编辑保持原样。重试期间提示和按钮保留，按钮显示进行中状态并禁用；重复点击会复用当前读取。已卸载页面的迟到结果不会写入页面反馈。项目 store 自身继续用读取代次丢弃较旧的列表响应。

路由上的 `projectId` 解析、现有工作流归属选择和服务端鉴权保持原路径。项目列表不可用不改变服务端授权结果，也不推断工作流 owner。

## 验证边界

`workflowLoadErrorOwnership.test.ts` 使用真实 Vue 页面和 Pinia 工作流/项目 store，通过受控 API 响应覆盖两个请求的成功、失败、重试以及路由切换与卸载交错。该回归验证前端请求和 DOM 状态，不代表真实后端、身份授权或真实浏览器视觉验收。
