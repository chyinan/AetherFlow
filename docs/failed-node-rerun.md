# 失败节点局部重跑

运行历史的失败节点提供“局部重跑”。先从服务端读取预览，列出要失效的节点（失败点及所有可达下游）和可复用的已完成结果；确认后创建独立运行，保留原失败记录。

## 执行契约

- 仅后端实例与持久快照都处于 FAILED，且节点列于 failedNodeIds 时可提交
- 复用已完成祖先和无关分支的输出，不重做它们的 AI 调用
- 失效范围采用原运行的不可变定义，当前编辑器中的未运行改动不影响重跑
- 变量由原始输入和保留节点的变量输出重建；清除失效根节点的嵌套输出和上下文
- 遇到无关的未完成、等待或失败分支会显示阻塞原因，不擅自补跑它们
- 相同源快照和失败节点的重复请求始终返回同一个派生运行；如派生运行再次失败，应从新的失败运行继续重跑
- PENDING 实例、PENDING 种子快照和唯一启动 Outbox 在同一本地事务中保存。由成功抢占 Outbox 的派发器恢复种子；后续恢复沿用持久快照和运行租约
- 重新执行的下游节点可能产生新的模型费用或外部副作用，预览确认前不会启动

## API

- GET /workflow-instances/{id}/nodes/{nodeId}/rerun/preview：返回 revision、eligible、invalidatedNodes、preservedNodes、blockers
- POST /workflow-instances/{id}/nodes/{nodeId}/rerun：请求 {"expectedRevision":"预览中的 revision"}，返回派生实例
- 源快照变化时返回冲突，要求重新预览；前端不会自动重发付费执行请求

## 回归覆盖

新增 Java 测试覆盖传递失效、输入重建、嵌套记录保留、终态资格、无关分支阻塞、租约并发、恢复幂等、事务提交后派发、重复插入、预览版本和 API 校验。新增前端测试覆盖范围预览、双击、关闭、导航切换、阻塞态和同版本重试。测试使用模拟执行器，不调用真实模型或第三方服务。
