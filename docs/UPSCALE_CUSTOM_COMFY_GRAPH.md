# UPSCALE 的 ComfyUI 执行图

## 场景

UPSCALE 节点在高级编辑里保存了自定义 ComfyUI 执行图，保存重载与派发都保留了该图，
实际执行却固定使用 LoadImage→ImageScaleBy→SaveImage 的默认图：自定义模型与插件步骤
全部无效，而普通缩放仍能成功，问题容易被当成"缩放正常"。

## 契约

- 显式有效的 API 执行图必须真的被执行
- 只有没有执行图（字段缺省，或只有导入的原图）时才走默认放大图
- 导入的原图（UI 格式）不是可执行图：按无执行图处理，不当作有效图执行
- 格式非法的执行图明确报错，不静默忽略
- 输入图像契约：放大执行图必须通过 `workflowBindings` 绑定源图输入（`sourceImage`），
  缺绑定明确报错
- 参数绑定沿用既有 `workflowBindings` 机制
- 输出提取沿用既有约定：读取任务输出中带 `images` 的节点
- 源码结论，未做真实插件执行验收

## 验证范围

Java 回归使用受控 ComfyUI 端点（MockRestServiceServer），断言实际收到的 `/prompt`
请求体：自定义图被提交、无图时提交默认图、缺源图绑定时报错、非法图时报错、结果提取
正常。受控端点不等于真实 ComfyUI 插件执行。
