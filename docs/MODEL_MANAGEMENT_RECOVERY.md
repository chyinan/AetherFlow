# 模型管理动作与读取恢复

主路由切换、熔断恢复分为管理写入及运行快照确认两个阶段。前置策略读取失败或实际 PUT／POST 被拒绝仍是操作失败；写入已成功返回而后置读取失败时，明确显示原动作、原目标及读取错误，不误报写失败，也不伪造主路由、熔断或健康快照。

此时下方信息还不能确认操作后的运行状态。用户可以换选、进入服务配置，或使用顶部／提示栏的刷新状态按钮；刷新只读取，不重复发送管理写。等待真实管理快照恢复前，页面与 store 均禁止再次提交切换／恢复。再次读取失败保留原确认事实并显示最新错误；显式演示回退仍保留确认提示与演示门禁，只有当前有效的真实管理快照成功才解除此限制。通用快照应用不会冒充管理确认。

操作等待时正常换选不取消已提交动作。成功仍应用新的全局运行快照，但保留仍在目录中的当前选择；选择已从真实目录移除时沿用合法 fallback，不强制回到旧操作目标。下一次管理操作使用当前显示选择。

原身份／请求代次、真实快照门禁、在途互斥及卸载重入策略保持不变，不自动重试管理写。写请求失败也可能是结果未知，原失败提示不构成服务端一定未执行的承诺。

新增回归使用正常 ADMIN／OWNER、真实 Vue／Pinia／Vue Router、页面／store／modelApi及映射器，底层API模块为内存 fixture。独立复核使用真实 apiClient 与受控 Axios adapter，覆盖实际路径、解包和读取重试。这些是 DOM／状态／前端派发证据，不代表真实浏览器、真实后端／Provider或生产运行验收。未修改后端、权限、依赖、持久化配置或用户设置。
