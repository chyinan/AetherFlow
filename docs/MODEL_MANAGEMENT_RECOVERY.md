# 模型管理动作与读取恢复

主路由切换、熔断恢复分为管理写入及运行快照确认两个阶段。前置策略读取失败或实际 PUT／POST 被拒绝仍是操作失败；写入已成功返回而后置读取失败时，明确显示原动作、原目标及读取错误，不误报写失败，也不伪造主路由、熔断或健康快照。

此时下方信息还不能确认操作后的运行状态。用户可以换选、进入服务配置，或使用顶部／提示栏的刷新状态按钮；刷新只读取，不重复发送管理写。等待真实管理快照恢复前，页面与 store 均禁止再次提交切换／恢复。再次读取失败保留原确认事实并显示最新错误；显式演示回退仍保留确认提示与演示门禁，只有当前有效的真实管理快照成功才解除此限制。通用快照应用不会冒充管理确认。

操作等待时正常换选不取消已提交动作。成功仍应用新的全局运行快照，但保留仍在目录中的当前选择；选择已从真实目录移除时沿用合法 fallback，不强制回到旧操作目标。下一次管理操作使用当前显示选择。

同一管理上下文进入服务配置再返回时，仍在途的原动作继续负责写入和确认读取，返回页面不会以写入前快照解锁管理按钮。如果原写入已确认、读取仍失败，返回时保留原动作提示并重新读取；只有真实管理快照才解除限制。没有未完成动作或确认提示时，返回仍重新读取。管理上下文变更仍按原策略清理，不自动重试管理写。写请求失败也可能是结果未知，原失败提示不构成服务端一定未执行的承诺。

回归使用正常管理角色、真实 Vue／Pinia／Vue Router、页面／store／modelApi 和映射器。跨页测试通过受控 Axios transport 核对管理写、确认读取、拒绝及原确认提示，设置目的页为路由夹具。这些是 DOM／状态／前端派发证据，不代表真实浏览器、真实后端／Provider 或生产运行验收。未修改后端、权限、依赖、持久化配置或用户设置。

## 已配置主路由与当前活动路由

服务列表区分两种标记：「已配置主路由」来自策略接口明确返回的首选服务；「当前活动路由」来自运行快照。备用服务在故障转移后可以是当前活动路由，但不一定是策略首选，仍可显式将其设为主路由。已是策略首选的服务不重复提交；目录推断顺序、演示数据和运行状态均不冒充已配置首选。设置只调整已有策略顺序，保留其他策略字段，不宣称运行中的活动路由已改变。

如果点击时快照过旧、最新策略已将目标置首，只读取更新后的快照，不重复写入。此时若状态读取失败，保留原读取错误和重试入口，不显示「管理写入已确认」；真正写成功但后续读取失败则维持原确认和重复写入门禁。


## 提供方配置保存与运行目录读取

设置页保存提供方地址、默认模型或启用状态时，以配置 PUT 返回的记录确认保存。卡片和重新打开的编辑框使用该配置回执；附带的运行目录读取只是展示补充，读取失败也不会把已经保存的配置误报为保存失败，不再提示用户重复提交。模型管理页的运行健康与路由状态仍需显式刷新，配置保存成功不代表模型已实际连接或推理验证通过。

配置 PUT 本身明确失败时，编辑框继续保留草稿和错误，用户可以修改后再次保存。配置目录读取的旧版默认模型兜底保持不变。回归使用 jsdom 和受控 HTTP 响应，不代表真实模型或设备验证。
