# 图像批量结果的完整交付

## 场景

工作流节点目录允许 `batchSize` 1–16，Provider 返回全部图片，但 ai-service 的图像执行器只保留 8 张并以 SUCCEEDED 结束，workflow-service 的异步产物登记同样只落 8 张，节点输出的 `imageCount` 也按截断后的数量上报。用户看不到第 9 张以后的图片，产物也不会被登记。

## 契约

- 1–16 张必须端到端完整交付：Provider 响应、产物登记、节点输出数量与前端展示一致
- 上限与节点目录的 `batchSize` 范围一致（1–16），不降低到 8
- 超过支持上限的响应属于异常，必须明确失败，不能静默丢弃多出来的图片
- 仍有界资源保护：单张图片体积上限不变
- 无效图片（空内容、非法 base64、超体积）仍然明确失败

## 验证范围

Java 回归使用受控 Provider 与受控产物存储，覆盖 16 张完整交付与数量、9 张不再被截断成 8、超过 16 张明确失败、空图片仍然失败、异步产物登记 16 张且登记次数一致。

受控 Provider 与受控图片不是真实 Stable Diffusion 推理或真实对象存储验收。
