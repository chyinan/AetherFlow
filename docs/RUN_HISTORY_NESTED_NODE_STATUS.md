# 循环子节点失败在历史查询中的呈现

## 场景

循环（ITERATION／LOOP）体里的某个步骤失败时，运行事件仍然是 `NODE_COMPLETED`，真实结果由事件属性 `itemStatus` 携带（`SUCCESS`／`FAILED`）。实时链路按 `itemStatus` 映射节点状态，失败会显示为失败。

历史查询此前把所有 `NODE_COMPLETED` 一律映射为 `SUCCESS`。整页刷新或新标签页打开历史运行时，该步骤被标成成功，时间线误导排错，而真实执行结果并没有变成功。

## 契约

- 历史查询在 `NODE_COMPLETED` 事件带 `itemStatus=FAILED` 时把节点状态映射为 `FAILED`
- 其余终态映射不变：普通节点的 `NODE_COMPLETED` 仍是 `SUCCESS`，`NODE_STARTED`／`NODE_RETRYING`／`NODE_WAITING` 与运行状态回退的既有解释保持不变
- 前端的终态保护不取消：历史查询与实时链路对同一事件给出相同结论，而不是靠前端放宽“成功不可改成失败”的保护来掩盖
- 真实运行状态、输出、历史与产物仍以运行时快照为准；本契约只修正历史查询对嵌套节点 `itemStatus` 的解释

## 验证范围

Java 回归覆盖：嵌套子节点失败时冷加载历史仍为失败；嵌套子节点成功时仍为成功；普通完成节点不受影响。用例直接构造真实 `RuntimeEvent` 序列并走真实历史查询服务。

受控事件回放不等于真实运行验收：真实循环执行、真实模型失败与真实历史数据的端到端展示未验证。
