# 并行执行时的失败节点归属

## 场景

A 与 B 并行执行，B 先成功、A 后失败。节点执行异常本身携带 A 的节点身份，但工作流协调器在等待节点结果时只向上抛出失败原因，丢失了节点身份；外层随后按 `context.currentNodeId()` 发布 `WORKFLOW_FAILED`，此时当前节点可能已经是成功完成的 B。

于是实时失败事件指向 B，冷加载历史时同一批事件也会把 B 标成失败，A 反而显示为仍在运行；终态保护会阻止把 B 从成功回退成失败，用户没有针对真正失败节点 A 的重跑入口。

## 契约

- 失败事件归属真正失败的节点，不被并行执行中最后完成的其他节点抢走
- 节点执行异常保留节点身份与原始失败原因，对外仍然抛出原始失败，调用方拿到的异常类型与信息不变
- 快照中的 `failedNodeIds` 一直是真正失败的节点，保持不变
- 终态保护、取消语义与既有失败传播保持不变

## 验证范围

Java 回归使用真实运行引擎，用确定的完成顺序（A 启动、B 启动、B 成功、A 失败）验证：失败事件指向 A、事件错误信息仍是节点原始原因、快照的 `failedNodeIds` 含 A 且不含 B、成功的 B 仍发布 `NODE_COMPLETED`。

受控执行器不是真实 Provider 或真实模型验收。
