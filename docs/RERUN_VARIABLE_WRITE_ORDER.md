# 局部重跑的变量写入顺序

## 场景

合法节点 a 与 z 都写全局变量 `completion`。原运行里 a 先写入 A、z 后写入 B，下游 d 使用
`completion`（值 B）后失败。只重跑 d 时，复用输出的变量按"拓扑深度 + 节点 ID"重建，
同深度的 a 与 z 会按字典序倒序合并，最终值变成 a 的 A：重跑读到的输入与原运行不同，
失败原因也会被掩盖。

## 契约

- 同名变量的最终值由原运行中最后写入者决定；局部重跑必须沿用源快照的真实完成顺序
- 复用节点顺序沿用源运行的完成顺序（PR #79 的分支跳过顺序修复保持不变）
- 不把整份最终变量复制进派生运行：派生变量只来自原始输入与被保留节点的输出，
  失效下游的输出不回流
- 同名写入本身仍被允许（既有契约只做提示），不禁用该场景
- 上游已完成节点不重复执行，独立输出与嵌套上下文保持原样

## 验证范围

Java 回归使用真实运行引擎与计划生成，覆盖：同名写入先后（z 后写则仍为 B）、不同节点
排序、仅下游重跑时下游读到原值、上游不重复执行。
