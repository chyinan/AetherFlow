# 离开前保存的跨工作流恢复

## 问题与恢复行为

当工作流 A 的“保存后离开”请求尚未返回时，用户仍可选择“放弃修改并离开”。进入 B 后编辑，再次尝试“保存后离开”，之前的页面局部等待锁会继续禁用按钮，即使 B 已经完成加载且没有保存请求。这会让 B 的正常离开保存依赖 A 的网络响应。

现在，关闭或替换未保存导航弹窗会释放该次导航的局部等待锁，并使其请求回调失效。新工作流可以独立保存；旧请求的成功、失败和清理回调都不能更新新弹窗的等待状态、错误或导航决定。

在同一画布选择留页或改选目标时，实际进行中的保存仍由工作流 Store 的 `saving` 状态防止重复提交。保存失败后继续保留当前画布、撤销历史、未保存标记与错误，可显式重试。保存期间继续编辑仍需再次保存，原有行为不变。

## 验证路径

- A 保存未决时丢弃离开，B 编辑后可立即保存；A 迟到成功或失败不解除 B 的等待状态
- B 可先保存并离开，随后 A 返回不改变新工作流 C 的图、历史或未保存状态
- B 保存失败后，A 迟到成功或失败不覆盖 B 的错误；重试包含 B 的编辑并仅批准当前导航
- 同一工作流 ID 的项目上下文切换仍能解除旧局部等待锁
- 留页或替换导航目标但仍处于同一画布时，保留真实保存的单写保护
- 既有离开保存、保存归属、导入持久化与地址规范化回归继续适用

## 范围与限制

只修改前端页面的局部请求生命周期，不改变实际保存请求、服务端状态、幂等机制、导航守卫批准规则或权限。选择丢弃不会取消已经发出的保存请求，A 的保存仍可能在服务端成功；本次修复只隔离过时回执及页面等待状态。

自动验证使用真实 Vue、Pinia、WorkflowPage、Vue Router 的 memory history 与受控 API。画布、检查器、运行面板和辅助 store 使用测试替身。不代表真实浏览器视觉、原生历史进程、真实网络、后端数据库、Provider 或部署验收。
