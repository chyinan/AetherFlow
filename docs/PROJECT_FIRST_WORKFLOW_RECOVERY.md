# 项目首次新建工作流：编辑器打开失败后的恢复

在项目空状态点击“创建第一个工作流”，输入名称后，项目页先打开包含项目和名称的空白编辑器。这里尚未创建后端定义；定义仍由编辑器里的原有保存操作写入。

- 打开编辑器期间保留名称弹框和等待提示，只处理一次提交。
- 如果编辑器加载失败，或者导航没有成功且仍停留在原项目页，保留当前输入并提供显式重试。重试沿用同一项目，名称仍按原规则裁剪首尾空白；不会自动重试。
- 点击关闭或按 Escape 会放弃草稿，并在仍等待本弹框的编辑器导航时停留在项目页。已经开始的较新目的地不会被关闭动作改写。迟到的加载结果不会提示旧错误，也不会结束后来打开的弹框的等待状态。
- 如果编辑器资源失效（例如发布后旧页面继续引用旧资源），同页重试不一定能恢复。持续失败时可以先复制名称，再刷新项目页重试。显式关闭和刷新均不会持久化未保存的名称。
- 项目新建、工作流重命名、已有工作流的打开及编辑器保存契约均不变。

回归通过真实 ProjectsPage、Pinia 和 Vue Router 的内存历史执行，模拟编辑器延迟加载、抛错、导航被拒绝和取代、关闭、返回及重试。测试覆盖中、英、日提示和不发送写入请求。未验证真实浏览器模块缓存、原生历史、布局或后端。

## 打开已经保存的工作流

项目卡片的“打开最近工作流”和工作流行链接仅发起导航，不修改定义。导航等待时在触发入口旁显示目标，同一目标不会重复发起；如果导航未成功并且仍在原项目页，该入口显示错误和重试。重试沿用原目标，即使列表排序发生变化。其他目的地开始导航后，旧回执不会再显示错误；正常打开再返回项目页也不恢复旧提示。行链接仍可通过修饰键在新标签页打开，不改变当前页的项目选择。

浏览器遇到发布后的旧资源时，同页重试不一定能恢复。持续失败可手动刷新项目页再尝试；页面不会自动刷新。
