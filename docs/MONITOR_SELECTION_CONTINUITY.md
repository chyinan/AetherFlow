# 监控事件刷新中的选择连续性

## 用户后果与修复

管理员在监控页已选中事件 B，或在刷新等待时点击 B，右侧详情应继续展示 B。原实现每次收到遥测刷新回执，都会无条件选择待复核首条或列表首条。即使刷新返回的列表仍包含 B，已显示的服务、事件内容和 Trace 也会突然改成 A。

现在只在新事件列表不再包含当前选中 ID 时使用原默认顺序：待复核首条、事件首条、空值。检查发生在新列表写入之后，采用此刻的用户选择，不提前快照请求发起时的旧选择，因此不会覆盖等待期间的新点击。

仅修改 `MonitorPage.vue` 的选择协调，不改变请求代次、身份或权限守卫、API、来源单项重试及其他页面；不新增主动刷新或新功能。

## 固定正常流程回归

新增 `frontend/src/pages/monitor/monitorSelectionContinuity.test.ts`，固定唯一合成已授权 ADMIN 和同一合成工作区。挂载真实 Vue 页面、i18n、Pinia 与内存路由，点击可见事件按钮及刷新／重试按钮，通过右侧服务、事件内容和 Trace 验证选择。治理与遥测读取只在模块边界提供内存合成值；文件和账号来源仅保留空值与来源状态枚举，不调用真实实现。

覆盖十项：

1. 初始默认 A，真实点击 B 切换详情
2. 刷新前已选 B，相同集合回执后仍为 B
3. 刷新等待中点击 B，回执保留较新选择且顶部刷新防重
4. logs 已返回、metrics 仍等待时点击 B，最终回执仍为 B
5. 同次等待中先 B 后 A，保留最后一次点击 A
6. B 确实移除后回退现存首条 A
7. B 移除后保留既有待复核条目优先级
8. 全空集合清空详情并显示空态
9. queue 显式单项重试的等待、防重、只请求该项、不重读遥测及保留 B
10. 刷新中选择 B，经 queue 部分失败及真实显式重试恢复后仍为 B
