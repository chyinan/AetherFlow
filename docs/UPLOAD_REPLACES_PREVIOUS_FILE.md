# 上传回执与已有文件选择的关系

## 场景

开始节点已绑定文件 A，用户再上传文件 B。上传成功后的回执按"节点当前值是否等于上传值"
判断，节点上还是 A，与 B 不等，回执被当作"期间有新选择"丢弃：A 不被替换，运行仍然使用
旧文件 A，正常上传等于无效。

## 契约

- 上传回执只替换**上传开始时**的旧值：上传期间用户没有改过文件选择时，A→B 正常替换
- 上传期间用户改选或清空文件时，保护用户新操作，丢弃迟到回执
- 上传期间用户改选后又改回原值时同样保护：归属代次已经变化，不能仅比较最终值
- 重叠上传时只有最后一次生效
- 切换工作流、删除节点后到达的回执不写入任何节点
- 上传失败不写入任何文件配置
- 归属保护（工作流、节点、代次）保持不变

## 验证范围

前端组件测试覆盖：已绑定 A 时上传 B 替换成功、无旧文件时上传写入、上传期间改选已有文件、
上传期间清空、改选后改回原值、重叠上传、切换工作流后的迟到回执。
