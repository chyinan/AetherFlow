# 结构化映射的应用反馈

## 行为

结构化映射编辑器点击“应用映射”后，实际节点检查器会把映射写入当前节点并回传配置。成功提示“已应用到节点，请保存工作流”应保留，直到用户继续编辑、切换节点、关闭面板或收到外部映射/输出变量替换。

这个提示只表示本地节点配置已应用，不代表工作流已保存到服务端或已执行。现有保存、预览、映射 JSON 类型和撤销/重做行为保持不变。

## 修复边界

- 原逻辑在自身配置回传时重新加载表单并清掉成功提示；映射实际写入成功，问题仅为缺少操作反馈
- 只认领当前节点、本次应用发出的映射对象、内容快照及输出变量的回传，不按内容相等认领外部替换；同对象在回传前被改写也不能认领
- 草稿变更同步清除旧反馈，防止排队的监听覆盖刚收到的应用确认
- 外部替换、撤销/重做、节点切换和关闭重开继续清除成功提示；等内容的新对象也属于外部替换
- 不新增自动保存、自动重试、去重或后端执行行为；用户重复点击仍遵循既有配置历史契约

## 验证

`StructuredMappingFeedback.test.ts` 使用真实 NodeInspector、StructuredMappingEditor 和 Pinia，覆盖无效 JSON 纠正后应用、连续显式应用、后续编辑、外部替换、撤销/重做、节点切换和关闭重开。保留既有结构化映射组件与保存重开回归。

测试中的目录与持久化 API 使用受控替身；jsdom 不代表真实浏览器视觉、辅助技术、实际网络、后端或 Provider 验收。

当前父层同步接收应用。组件未增加父层接受/拒绝协议，保留既有乐观提示行为。人工在同一响应式批次内调用应用、撤销、重做，最终返回同一映射对象和相同内容时，组件无法观察中间历史操作；正常用户分次操作的撤销/重做会清除提示。本次不为这一程序化原子批次增加接口或改变历史存储。
