# 任务派发抢占失败后的恢复

消费派发消息时，只有 `PENDING` 或 `QUEUED` 允许抢占为 `DISPATCHING`。第一次状态条件更新失败后，重新读取任务并重新判断派发资格，再至多抢占一次。

- 入队状态在首次读取后才提交（`PENDING` 变为 `QUEUED`）时，保留原来的快速重试，不必等待超时扫描。
- 如果任务已被取消、已完成、已被其他消费者抢占或进入重试/超时流程，忽略这条派发消息，不修改状态或再次投递给工作队列。
- 如果第二次条件更新仍失败，则不发布工作消息，交给赢得抢占的一方或既有恢复机制处理。

`mvn -pl backend/task-service -am test` 中的回归测试使用真实消费方法和任务状态服务，在数据库适配边界模拟状态条件更新，并观察工作消息的投递。覆盖上述交错，不依赖并发线程的调度时机。未启动真实 MySQL、Redis、RabbitMQ 和 AI 服务；本修复不改变消息重投策略，也不承诺跨服务恰好执行一次。
