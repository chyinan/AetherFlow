# 工作流入口与模板首跑的请求归属

## 修复的用户路径

1. 打开未指定名称或项目的空白工作流入口，辅助列表尚未返回时进入另一工作流或命名草稿，并编辑或应用模板。原实现等辅助读取完成后再次清空全局画布，导致新内容、身份和撤销历史丢失；离页重入也会受影响。现在只在进入空白入口时同步清理，不在旧读取结束后重置新画布。
2. 打开模板列表后切到另一工作流，或离页重入。原请求的成功会在新页打开弹框，失败会覆盖新页运行错误，旧等待也会暂时阻塞新页重新加载模板。现在成功导航关闭旧弹框并废弃请求代次，卸载释放旧等待；旧成功、失败和 finally 均不能覆盖新请求状态。拒绝导航仍保留原页请求和选择。
3. 未保存模板 A 点击运行，等待运行历史或输入准备时替换为模板 B。两张画布的 ID 都是 new，仅核对 ID 会让旧点击保存并运行 B。现在派发前绑定点击时的编辑代次；准备期间换模板或编辑配置后，必须重新点击运行。未改内容、拒绝模板替换和正常首次保存后的地址规范化仍可继续。

## 行为边界

- 派发后继续编辑同一工作流时仍记录原运行回执，由已有未保存导航确认决定是否离开；不会把服务端已确认的运行隐藏成回执丢失。
- 请求失效只停止旧回执对当前页面的影响，不承诺中止已发出的网络请求或撤回服务端已经收到的运行。
- 模板和节点能力仍通过原有接口读取，服务端仍执行最终定义和能力校验。
- 未修改后端、Provider、依赖、设置或权限，也不改变已有运行重试的幂等确认语义。
- 仅以受控 API 验证页面流程，不能据此声称真实音频转录、模型生成或文件成品已经成功。

## 回归验证

- workflowEntryLifecycle.test.ts：四种辅助读取的迟到返回、模板应用、卸载重入和读取失败
- workflowTemplateLifecycle.test.ts：跨页成功/失败、弹框清理、重新加载、重复点击、拒绝导航、旧 finally 与新请求交错
- workflowTemplateStartLifecycle.test.ts：历史/输入准备期间换模板、配置修改、明确重新启动及拒绝替换对照
- 与既有模板、启动幂等、保存、导航、首跑向导和人工审批测试一同回归，保留原有断言和超时门限

交互验证使用 jsdom、真实 Vue/Pinia/Router 和页面组件；API 传输及部分无关组件受控替换。真实浏览器布局、浏览器进程历史、实际网络时序、后端、数据库和 Provider 不在此次验证结论中。
