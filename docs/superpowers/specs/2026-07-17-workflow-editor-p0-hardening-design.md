# 工作流编辑器第一批 P0 加固设计

## 目标

在不改动已验证的“视频输入 → Whisper STT → LLM 总结 → Markdown 导出”主链路前提下，消除工作流编辑器中会误导用户的无效交互，并让加载失败与未保存状态可见、可恢复。

## 范围

本批次只处理以下三类问题：

1. 工作流详情加载失败后，不再静默显示同名空白工作流。
2. 条件、代码和模板转换节点的属性面板只展示后端真实支持的字段，所有可编辑控件都写回节点配置。
3. 工作流存在未保存改动时，站内跳转、浏览器刷新和关闭页面均给出离开确认。

以下内容不在本批次实现：单节点独立运行、隔离代码执行器、多条件 `IF/ELIF` 规则组、项目与工作流后端关系重构、运行结果预览与下载。

## 真实后端契约

### 条件节点

后端 `ConditionNodeExecutor` 只支持一条条件表达式：

- `variable`
- `operator`
- `value`
- `trueBranch`
- `falseBranch`

前端删除当前虚假的 `IF/ELIF` 添加、删除按钮，改为与上述字段一一对应的表单。`EXISTS` 和 `NOT_EXISTS` 不需要比较值，界面相应隐藏该输入框。

### 代码节点

后端只持久化 `language`、`code` 和 `outputVariable`。真正执行代码需要独立沙箱，默认关闭。因此前端移除未绑定的输入参数、输出参数增删和代码辅助图标，保留真实字段并明确提示当前运行限制。

### 模板转换节点

后端从工作流上下文读取模板变量，只配置 `template` 和 `outputVariable`。前端移除虚假的输入参数增删入口，保留模板编辑、可用变量说明和输出变量配置。

### 单节点运行

当前没有单节点运行 API。属性面板顶部无响应的播放按钮直接移除，避免形成虚假可用性。

## 加载错误处理

`workflowApi.getWorkflow` 仅在 `workflowId === 'new'` 时返回空白工作流。对于既有工作流，所有候选后端定义请求失败后抛出最后一次错误；没有可解析候选 ID 时抛出明确错误。

工作流 Store 增加 `loading` 与 `loadingError` 状态。页面在加载中显示加载态，失败时显示独立错误页，包含错误信息、“重新加载”和“返回项目”操作。失败时保留当前内存中的工作流，不用空图覆盖已有内容。

## 未保存保护

工作流页面负责路由和浏览器生命周期，因此保护逻辑留在页面层：

- `onBeforeRouteLeave`：当 `workflowStore.dirty` 为真时调用确认提示。
- `beforeunload`：当存在未保存内容时阻止刷新或关闭。
- 保存成功或没有改动时不拦截。

确认文案使用国际化键，不新增自定义弹窗组件。

## 组件边界

- `WorkflowPage.vue`：加载态、错误态、重试和离开保护；只负责编排。
- `workflowStore.ts`：维护工作流加载状态，保证失败不覆盖当前图。
- `workflowApi.ts`：定义“既有工作流必须真实加载成功”的接口语义。
- `NodeInspector.vue`：根据后端契约编辑节点配置，不引入新的全局状态。

## 验证

先增加一个工作流编辑器 P0 契约检查脚本并确认在旧代码上失败，再做最小实现使其通过。最后执行 TypeScript/Vite 构建和现有全部工作流契约检查，确保主演示链路映射没有回归。

## 设计自检

- 无占位项或待定字段。
- 不修改 STT、LLM、Markdown 导出执行逻辑。
- 不实现后端尚不存在的单节点运行和多条件规则组。
- 错误、加载和未保存状态均有唯一责任层。
