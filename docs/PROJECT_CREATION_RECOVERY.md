# 项目创建等待与恢复

## 用户路径

从项目页或首次使用的空状态打开“新建项目”，填写名称与场景后提交。在同一弹框请求未返回前，创建按钮和输入项处于等待状态；连续点击或重复提交只派发一次请求。

等待期间仍可关闭弹框或离开页面。关闭窗口不等于取消已提交的服务端请求，界面会明确提示这一点。成功回执仍将新项目加入列表，但已经关闭、重新打开或卸载的旧弹框不能关闭新草稿、抢走项目选择或导航回项目页。

当前请求失败时保留名称和场景，显示可恢复提示并恢复输入与创建按钮。客户端不能仅凭响应失败断言服务端没有创建成功，用户应核对项目列表后再显式重试，避免重复创建。没有自动重试、删除补偿或后端幂等保证。

项目列表还在读取时也可以创建项目。旧列表晚到不会抹掉本次读取期间已确认的新项目；如果列表先看到了新项目，随后创建回执不会重复插入同一 ID，也不会覆盖列表已有的数据。创建完成后才发起的新读取仍以服务端列表为准，不永久保留本地记录。列表提交后保留仍有效的当前选择；原选择已不存在时回退首项，空列表清空选择，使卡片高亮与实际项目一致。

## 实现边界

- 项目创建弹框以代次标识请求归属；旧成功、失败和 finally 不影响新弹框的等待状态和提示
- 项目 store 仅保留已确认的创建记录；仅当前有效页面回执选中新项目
- 当前创建成功直接关闭当前弹框，无需再次导航到已经所在的项目页
- 关闭后重新创建属于新的明确提交，可以与旧请求并行；不承诺跨弹框或跨页面合并相同名称的请求
- 未改变工作流新建/重命名/删除、后端、依赖、权限或用户设置

## 验证

回归使用真实 Vue、Pinia、Vue Router、ProjectsPage、projectStore 和 projectApi，HTTP 边界使用受控替身。覆盖重复提交、失败后的显式重试、关闭重开、旧成功/失败与新等待交错、新请求先完成、卸载重入、当前项目选择、名称裁剪和三种界面语言。

列表连续性回归另覆盖创建与列表响应的两种顺序、辅助工作流读取延迟、最新请求优先、旧弹框关闭后的新选择、部分读取失败、服务端后续移除记录和项目选择回退。首次加载的卡片保留与继续创建工作流入口均有 DOM 与路由断言；当前没有页面直接调用 store 的 refreshProjects，相关测试仅保护该 store 方法的一致行为。

这些测试证明前端派发和状态归属，不代表真实浏览器布局、原生历史导航、后端重复记录、服务端幂等、真实 Provider 或部署验收。没有在生产环境创建项目。
