# 可恢复批处理循环

ITERATION / LOOP 沿用原节点类型。无 `bodyNodes` 时保留旧行为；非空循环体在设置面板以顺序步骤编辑。循环体每层最多 100 个步骤、最多 1000 项/轮次、最多 8 层，作用域节点 ID 总长不超过 128 字符。

## ITERATION

- `inputVariable`：数组变量；例如字符串文件 URL 列表或提示词列表
- `itemVariable`：当前项的变量名，默认 `item`
- `indexVariable`：从零开始的索引，默认 `iterationIndex`
- `maxIterations`：处理项数上限；超过的条目在输出中标记 `truncated`
- `concurrency`：同时等待外部完成的条目数，1–8，默认 1；同步步骤仍顺序运行
- `failureStrategy`：`STOP` 停止继续调度；`CONTINUE` 保留失败结果并处理其余项
- `outputVariable`：最终逐项变量结果；每项失败信息在节点结果的 `results` 中可见

已有同步成功结果继续保持 `{item, variables}` 形状；结构化运行详情另含 `index/status/error`。在检查器“上次运行”中可分页查看逐项状态、输出和错误。

## LOOP

按顺序执行每轮步骤，把 `outputVariable`（或 `inputVariable`）的新值回填为下一轮状态。`stopWhen` 与次数上限控制终止，索引默认 `loopIteration`。LOOP 顺序执行，不并发修改状态。

## 执行与恢复

每个叶节点获得稳定路径，例如 `batch/iteration-0/transcribe`。完成输出由运行协调线程统一写入快照，并确认持久化后才开始下一步骤；工作线程不直接写快照。进程恢复复用已落盘结果。异步模型任务使用稳定摘要幂等键，长度保持在任务服务限制内。

成功、失败、人工审批和子流程回执均按叶节点地址恢复，完成一个等待项后再推进根循环。失败策略为 CONTINUE 时单项失败不会把整个循环标为失败。根节点统计不会把每个内部步骤当作额外顶层完成节点。

任何远端调用在“远端已完成、结果尚未落盘”的中断窗口都无法仅靠本地检查点保证 exactly-once；自定义 HTTP 的有副作用操作应由服务端提供幂等机制。STOP 不撤销已经发出的远端调用。

## 顺序体范围

循环体是有序步骤，不是任意子 DAG。分支条件、开始/结束节点以及 HTTP BRANCH / 人工拒绝 BRANCH 模式不直接放入循环体；请把带分支的步骤保存为固定版本子工作流后，通过 SUBWORKFLOW 步骤调用。嵌套定义继续受保存校验和现有能力预检约束。

失败节点重跑以根节点为粒度：重跑失败循环会失效该根的全部条目和作用域缓存；保留其他已完成根的产物。页面提交前展示这一范围。
