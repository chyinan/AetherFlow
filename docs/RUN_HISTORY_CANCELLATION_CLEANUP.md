# 运行历史：取消后的外部任务清理

运行收到后端的取消确认后，运行状态为「已取消」；关联任务是否已清理，仍以「外部任务清理」中的状态为准。「重试任务清理」只重试这一步，不重新运行工作流。

运行取消与节点结果分开呈现：服务端事件或节点摘要明确返回 `CANCELLED` 的节点显示「已取消」，已有成功、失败和跳过结果不被取消摘要改写。取消接口只返回清理回执，不返回节点身份；因此不会根据可能过期的当前节点推断取消结果。已取消运行中尚无终态证据的节点显示中性的「最后记录：…」，保留原始记录，后续权威历史仍可补齐实际结果。缺少耗时的终态或最后记录不显示「等待中」。这些文案不表示外部任务已经停止。

- 如果重试请求没有收到确认，界面显示「未能确认任务清理重试请求」及具体原因，不把它写成状态读取失败，也不声称服务端没有处理请求。
- 定时读取还在进行、读取失败或仍返回同一次清理结果时，保留上一次重试的提示。真实的读取失败仍单独提示；如果发现更新的清理进展或已经结束，以确认的清理状态为准，不推断是哪个请求完成的。
- 如果服务端仍允许重试，可以手动再次发起。详情不会自动再发一次重试请求；离开本次详情后也不会把旧提示带到另一条记录，或带入重新打开的记录。
- 取消回执、后续读取和手动重试可能交错返回。详情与列表保留服务端已确认的较新清理进展；较旧的失败不会重新显示重试，已完成的清理也不会退回处理中。同一次尝试的完成结果仍可接替较早读取到的处理中状态。

回归挂载真实运行历史、Pinia 和 Vue Router，通过受控的 Axios 传输复现重试失败、定时读取、状态推进和切换运行；不连接真实后端、任务服务或浏览器。
