# 连接目录的全量与局部结果

## 场景

首次列表读取未完成或失败时创建连接，存储把"空列表 + 新连接"标成目录就绪，并丢弃初始
读取：已有连接从选项里消失，用户以为连接被删除；刷新按钮此时只做一次探测，不能补齐
目录。

## 契约

- 全量目录与局部保存结果分开保存，界面看到的是两者合并去重后的视图
- 目录没有完整读取成功前不宣称就绪（`ready` 只反映全量目录是否读到）
- 局部保存结果不因目录读取失败或尚未完成而丢失；同一个连接以本地保存结果为准
- 目录读取失败保留错误并允许真正的列表重试；刷新按钮执行完整列表读取并随后探测
- 连接消失只说明目录尚未读到，不等于服务端删除了连接
- 写请求去重、只读部署连接标记与保存反馈保持不变

## 验证范围

前端 store 与选择器测试覆盖：首次目录未完成时创建连接（不就绪、局部结果保留）、目录
完成后合并去重（已有连接不消失）、目录读取失败后创建并重试补齐、重复回执按 ID 去重。
