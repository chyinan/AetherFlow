# Ollama 流式响应的读取方式

## 场景

固定依赖 `ollama==0.4.5`：其异步与同步流的每一块都是 `GenerateResponse` 对象，不是字典。
流式读取按"是字典才取 response"处理，于是每一块都被判为空，模型正文全部丢失：
调用方只收到结束标记，Java 侧拿到空回复。

非流式路径不受影响：`GenerateResponse` 提供了 `get()` 兼容读取。

## 契约

- 按实际 SDK 类型读取正文：优先取对象属性，其次按下标读取，最后回落到旧字典格式
- 空块跳过，终块（`done` 且正文为空）不产生额外事件，结束语义不变
- Provider 异常原样冒泡，客户端与流迭代器仍按既有语义关闭，取消语义不变
- 旧字典格式继续支持
- 同步与异步流式路径使用同一读取规则

## 验证范围

Python 回归使用固定依赖里真实的 `GenerateResponse` 类型（不是真实模型推理），覆盖：多块
流、空块、终块、旧字典格式、Provider 异常、消费端取消。
