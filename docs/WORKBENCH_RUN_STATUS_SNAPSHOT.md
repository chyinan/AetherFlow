# 个人工作台：独立读取的运行状态

工作台分别读取进行中各状态、失败与完成列表，不把它们当作同一个事务快照。运行在请求之间结束时，原来的活动响应和终态响应可能同时包含相同运行 ID。已确认的终态优先；该运行只留在对应的失败或完成区，旧活动行不再提示仍在执行或等待审批。同一轮活动读取从发起时就记住已确认的终态，读取结束后只保留与该活动快照重叠的 ID。即使活动响应仍在途中，终态区重读、失败或该行滑出当前页也不会使已确认过期的活动行重新出现。重新读取活动区时按本次请求重新比较；离开工作台不保留缓存。

没有终态证据时继续显示已收到的活动行，不等待其他区块，不把终态读取失败等同于活动结束。各状态读取范围、并行请求、单区重试、部分失败说明、终态计数及详情链接不变。若异步确认终态时被移除的活动链接仍持有焦点，将焦点保留在原区块标题；不改变其他位置的焦点。

验证使用 Vue、Pinia、内存路由、jsdom、真实前端 API 映射和仅允许合成运行列表 GET 的 Axios 适配器。覆盖成功与失败终态两种响应顺序、局部刷新、部分失败和焦点控制；未用真实浏览器、读屏器或后端。

同一活动区也可能收到同一运行的多份快照。例如审批恢复时，WAITING 页先读到旧的待审批状态，RUNNING 页随后读到已恢复状态；不能因为 WAITING 是后合并的分页就把真实进展覆盖掉。工作台保留响应的原始 `updatedAt`，按同一时钟基准的严格先后选择同 ID 较新快照，不按请求到达顺序判断。无时区时间按服务端本地墙钟比较，不套用浏览器时区；有明确偏移的时间只与其他明确偏移比较。缺失、相等、无效或不具有共同时钟基准时保留既有确定性选择。此处只修正同 ID 活动行的状态与摘要，不重排列表，不改分页、重试、详情导航或原有终态优先规则。
