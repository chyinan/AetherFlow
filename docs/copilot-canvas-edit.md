# Copilot 直接编辑画布

在工作流编辑器打开 AI Copilot，选择“直接编辑画布”，输入具体要求。编辑模式默认开启；“对话”模式继续用于问答和排错。

当前画布超过 100 个节点时，Copilot 会显示节点数量和上限，并停用直接编辑的发送和「设计工作流」快捷操作。已输入的草稿不会丢失；可以切换到「对话」继续问答，或在画布缩减到 100 个节点以内后直接发送。建议下一节点和解释错误不受此限制。

在「对话」中发送新的自由输入后，消息区会滚到新一轮。停留在底部时，消息区会跟随逐段生成的回复；向上翻阅旧消息不会被拉回底部。手动回到底部后，下一段回复会继续跟随。

面板右上角“新对话”会取消尚未完成的聊天或编辑请求，清空当前聊天上下文并退出旧的规划状态。画布、模型选择和旧历史记录保持不变。新对话仍能读取当前画布，但不再读取上一段聊天；刷新或重新打开面板会保留当前会话选择。

恢复已记住的会话，或列表自动找到当前工作流会话后，若历史加载失败，编辑页会保留会话和输入，暂停按默认模式发送。点击“重试”成功后按历史恢复模式：规划会话继续规划，空历史或普通聊天历史解除恢复锁；重试再次失败仍保留输入和重试入口。用户也可以明确选择“对话”或“直接编辑画布”后继续当前会话。

「建议下一个节点」和「解释最新错误」也会显示新的聊天回复及其结果；上翻阅读旧消息后仍不会被拉回底部。两项快捷操作都会保留输入框中未发送的草稿。

首次直接画布编辑若服务端已完成 `prepareTurn` 并持久化用户请求、随后模型或编辑响应失败，服务端会在错误响应中附带该次请求确切的会话 ID。只有当前仍是同一工作流/会话作用域中的同一待处理编辑、请求没有取消且本地尚无已确认会话 ID 时，客户端才采用此 ID；它会使更早开始的自动发现历史失效，并让下一次编辑续用正确会话。此恢复仅适用于收到带 `canvas-edit-failure` 类型和有效会话 ID 的服务端错误响应。连接中断/超时导致错误响应未到达、`prepareTurn` 之前的错误以及没有该元数据的旧服务端错误，都无法确认新建会话 ID；客户端不会按历史文本或时间猜测会话归属。由于失败发生在持久化用户请求之后，恢复出的会话可能含有该用户请求但没有 AI 回复。

“新对话”及切换工作流或未保存草稿会清除旧会话的恢复锁。旧重试的迟到成功或失败不能影响新会话，即使新会话首轮发送失败、尚未取得会话 ID。未预存会话选择时，后台发现历史的过程中仍可发起新请求，已有新回复及其会话选择不会被迟到历史覆盖。

示例：

- “创建开始 → LLM → 输出流程，使用当前模型，用中文回答问题。”
- “把 LLM 节点改名为中文助手，温度设为 0.3，提示词改为总结输入文本。”
- “在摘要和输出之间插入导出文档节点，并调整连线。”
- “删除指定节点，并把上游直接连接到下游。”

AI 返回修改后，客户端先在候选图执行整批操作，再通过服务端节点目录、配置和 DAG 校验。通过后自动应用为未保存草稿，顶部“撤销”可以一次恢复整批修改，“重做”可以再次应用。保存和运行继续使用原有按钮。

生成期间手动修改画布、切换工作流或取消编辑会阻止旧响应应用。历史消息仅保留用户文本和说明，不会在刷新或打开面板时重新执行操作。模型只能使用当前可用节点目录；不支持的能力会要求澄清。节点类型、必填配置和运行时能力仍由服务端校验。

## 接口

`POST /api/copilot/canvas-edit` 接收现有 Copilot 请求结构：`prompt`、`conversationId`、`workflowId`、`projectId`、`provider`、`model` 和脱敏后的 `context`。

响应包含普通 `message` 和 `edit`。`edit.status` 为 `READY`、`NEEDS_CLARIFICATION` 或 `NO_CHANGE`；只有 `READY` 可以包含操作。操作限于 `add_node`、`update_node`、`delete_node`、`connect`、`disconnect`，每批最多 80 项，画布最多 100 个节点。

候选图经 `POST /api/workflows/drafts/validate`（`recipe: CANVAS_EDIT`）进行只读校验，保留租户归属和后端版本检查。运行时未就绪会显示草稿警告，运行按钮仍执行服务端 fail-closed 预检。

更新前端代码时，需要重建 `nginx` 镜像；Nginx 静态文件来自镜像内构建产物，并不读取 `frontend` 导出容器的数据卷。

## 「建议下一个节点」的添加回执

普通 Copilot 快捷操作给出的单节点建议，只有编辑器实际添加了节点才会显示「已应用」。例如在回复后撤销了原节点，添加不会改动画布，也不会把建议标为已用；恢复原节点后可以重试同一建议，或根据当前画布重新获取建议。回复尚在生成时也可以点建议，最终消息到达不会清除成功或失败回执。重试添加本身不会再请求模型，也不会保存或运行工作流。

回归覆盖真实工作流页、Copilot 面板、Pinia、Vue Router 和前端 SSE 解析，使用 jsdom、受控接口与 SSE 响应，未连接真实模型或浏览器。
