# 工作台局部重试的恢复位置

## 场景与证据

本轮基于维护分支 `ed347e543cb918ab22d0c20f3c86cc426b01808f`，只处理个人工作台的“某区块读取失败 → 在该区重试 → 继续编辑或打开运行详情”流程。已有四区布局、独立读取/重试和权限边界保持；不重做工作台或运行历史页。

原错误提示内的“重试”按钮在开始加载时随错误分支卸载。按钮刚被键盘或程序化聚焦，点击后便不再存在于 DOM，焦点落到 `body`，用户失去刚才的恢复位置。同类结构存在于继续编辑，以及进行中、失败待查看、完成结果的错误/部分失败提示中。

两个不依赖新增 ID 的基线反例分别聚焦完成结果、继续编辑的现有重试按钮，点击后由内存读取替身同步切为 loading。加载提示已出现，实际焦点标签均为 `BODY`，而非同区稳定的 `H2`。这是同一种恢复位置缺陷在两个组件中的证据，不是多个独立业务故障，也不是实际浏览器键盘验收。

## 最小恢复契约

- 四个区块都有稳定的二级标题 ID、DOM ref 和 `tabindex="-1"`；区块及其错误/部分失败提示以该标题具名
- 局部“重试”的可访问名称包含原有区块名，沿用中英日现有翻译，不再只读出无上下文的“重试”
- 只有用户主动点击错误/部分失败内的重试时，先同步将焦点置于同区稳定标题，再沿用原读取调用；使用 `preventScroll`，不新增滚动跳转
- 标题有真正的 focus outline 样式，不只依赖阴影。`tabindex="-1"` 不将标题加入普通 Tab 顺序
- 已经 loading 的局部入口不重复派发；陈旧离线按钮点击仅作为防御测试，不描述为真实可到达的交互路径
- 不在成功、失败、异步回执、下一帧或组件卸载后再次回焦。因此用户等待期间主动移到其他链接，较晚回执不会把焦点夺回

页首刷新、各运行区标题旁的刷新、初始读取、身份监听、卸载清理、store、API、分组、计数、排序、链接和路由实现均未改动。没有保留旧数据、添加缓存、恢复草稿或引入额外确认层。

## 状态与继续操作

| 状态 | 位置与下一步 |
| --- | --- |
| 错误或部分失败提示 | 重试按钮名称明确所属区块，区块原有原因与状态提示保留 |
| 主动点击局部重试 | 读取前同步聚焦标题；错误按钮卸载后仍能识别当前区块 |
| 加载中 | 原加载提示继续呈现，兄弟区不被重试动作重新读取 |
| 成功返回 | 标题位置保留，数据/空态沿用原含义；可以继续打开原运行详情链接 |
| 再次失败 | 原错误提示再次出现，可显式重试，没有自动无限重试 |
| 等待期间主动移开焦点 | 较晚成功或失败均不回焦，尊重较新意图 |
| 等待期间离开页面 | 不注册迟到的焦点动作，不影响页面之外的后续焦点 |

没有待提交表单。取消或中断就是停止重试、改做其他事或离开页面；真实资源请求的防重、身份清理与竞态仍由已有实现负责，本轮固定替身不重复宣称验证这些机制。

## 验证方法与限制

唯一执行白名单为 `frontend/src/pages/home/PersonalWorkbench.recoveryPresentation.test.ts` 中经全文逐项审阅的 14 项用例。实际挂载两个呈现组件与 i18n；身份固定为一个普通用户，完整 mock homeStore，不初始化真实 Pinia、身份 store 或 API。读取替身仅同步切换合成资源状态并返回 deferred，所有 pending 均在清理时释放。API client、fetch、XMLHttpRequest、WebSocket、EventSource 和其他业务动作均禁止调用。

内存路由只用工作台、`/runs/:id` 轻量占位和不执行真实业务的空占位；成功后的链接测试只进入带对应 ID 的占位，不读取文件或挂载真实运行详情、编辑器或身份守卫。

覆盖两个精确焦点反例、部分失败、四区名称/唯一 ID/具名关联、同步读取前的焦点位置、成功后的链接、失败再试、较新焦点、卸载、loading 防御、既有成功/空/计数/链接，以及三语恢复名称。基线为 10 项失败、4 项通过；不是 14 个 Bug。实现后保持原有期望的 14 项初次全部通过。

首次应用类型检查发现新测试的一处 TS2339：Vue Test Utils 的 `get` 返回类型排除了 `exists`。将该行等价改为 `find(...).exists()`，期望仍为 true；两个精确焦点反例及其他期望未变。基线与最终文件不逐字相同，不能省略这次纯测试类型修正。首次失败日志保留，最终应用/构建配置类型检查均退出 0，Vite 生产构建退出 0。

构建产物确认标题 focus outline 为 solid、2px、offset 4px、颜色 `#2563eb`；这只确认样式被生成，不是像素或对比度验收。构建仍提示既有的大于 500kB 分块，最大工作流页约 565.08kB，不据此声称性能验收。

最终文件的 14 项全部通过，独立审查也在类型修正后重新执行同 14 项并全部通过（2026-10-17 18:23 UTC）。两组件完整源码已独立复核，没有剩余源码/受控 DOM 阻断。
