# 知识库详情检索的导航与局部状态恢复

## 使用场景与修复

同一正常用户在 ready 知识库 A 点击搜索后，若请求仍在等待，返回列表再打开 ready 知识库 B，B 会沿用旧的局部等待状态，导致非空查询也不能提交。A 已失败后离开，或返回列表后 A 才失败，也会把旧局部错误带到 B。

修复只涉及 `frontend/src/pages/knowledge/KnowledgePage.vue` 的页面局部检索生命周期：

- 返回列表、打开详情时递增请求标识并清理局部等待／错误
- 每次有效检索捕获自己的标识，只有当前标识的失败与结束回调可更新局部状态
- 不取消后端请求，不修改 API、store 的检索结果处理、身份、权限或文件功能
- 保留查询去空格、topK 规范化、当前等待时的按钮禁用，以及当前失败后的保留查询和显式重试

同一个知识库离开后重新打开，也会获得新的局部生命周期，避免只比较 dataset ID 而误认旧请求为当前请求。

## 补充：从列表打开知识库详情的请求归属

打开知识库详情前需要读取该库的文档列表。快速先点甲、再点乙时，较早的甲请求可能先结束；它不能替仍在等待的乙打开详情，否则会把尚未加载的乙显示成暂无文档，并过早呈现检索操作。若等待期间切换到新建向导或返回列表，旧读取的成功与失败也不应离开或遮挡当前页面。

页面为打开详情单独记录请求归属。连续选库、开始新建、返回列表或离开页面会让上一请求不再写入视图和错误提示；当前请求成功照常进入详情，当前请求失败仍可针对该库重试。保留已有读取、缓存、检索和写入行为，不取消后端请求。

`KnowledgePage.datasetOpenIntent.test.ts` 使用真实页面、Pinia、内存路由、知识库 API 和 Axios 响应处理，只替换传输以控制两个合成数据集的空列表回执和 HTTP 503。验证页面状态和 GET 次序，不涉及真实文件、浏览器或后端。

## 补充：知识库目录不预取未打开的数据集文档

进入知识库页面时，数据集目录成功不再依赖默认选中库的文档读取。原来目录已经返回，但随后自动读取第一项文档列表遇到 HTTP 503，页面仍被整个错误面板覆盖；用户无法搜索目录，也无法打开其他健康的数据集，重试目录会再次卡在同一项。

页面现在以 `includeSelectedDatasetContent: false` 读取目录，显式点击数据集后才沿用现有的文档读取和重试流程。目录本身失败仍显示错误而不是「暂无结果」；当前显式打开失败仍可只重试该库。`loadSurface` 的选中文档预取默认保持开启，其他调用方行为不变。不新增请求、自动重试或后台加载，不修改数据、导入、上传和检索流程。

`KnowledgePage.catalogReadRecovery.test.ts` 的 4 项验证使用真实页面、Pinia、内存路由、知识库 API 和 Axios，只替换传输，模拟两个 ready 数据集、空文档与 HTTP 503；文件 store 整体替换且禁止真实网络。包含首次进入、目录失败后手动恢复、按名称筛选再打开健康库、当前文档失败重试以及共享 store 默认行为。相同回归的首次 3 项在精确基线中 2 失败、1 通过，修复后新增默认行为对照共 4 项通过。没有真实后端、文件持久化或浏览器视觉验收。
