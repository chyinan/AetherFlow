# 运行历史的信息层级与渐进展开

## 本轮场景

普通已登录用户进入运行历史，通过名称、工作流或状态找到一条记录，选中后查看该次运行的详情、节点时间线和日志。只调整这一条流程的页面呈现，不改请求协议、筛选计算、运行控制或服务端行为。

基线为维护分支提交 `70ffd247e78157e2c8a5a2fcd082659b1b58a692`。此前分页、深链、重复清除草稿、取消和日志时区修复继续保留。

## 设计依据与可核实的变化

- 原页面在整个操作区上方放置四张大统计卡，再在侧栏连续放置筛选和完整 ID 表单，结果位于其后。本轮把相同口径的四项统计归入“运行记录”的紧凑定义列表，统计范围说明只出现一次；“本页匹配记录”标题与匹配数紧邻结果。
- 列表原先以机器运行 ID 为粗体主信息，工作流名称是次级小字，而详情恰好以工作流名称为主。本轮统一名称优先，保留完整 ID、状态、开始时间和成品数；长名称可换行，并保留完整标题。
- “按完整运行 ID 打开”是独立于列表筛选的另一项任务。本轮用有明确标题的原生 `details` 承载，默认收起，展开、关闭不卸载表单，因此不会清空草稿。没有使用频率数据证明它对所有人都是低频入口；这是基于本轮查找场景的设计选择，仍需真实用户验证。
- 路由目标同时驱动选中边框、选中文字和 `aria-current`。详情尚未读完时，不把保留在 store 中的旧详情标作当前路由选择。
- 主动点击记录或提交有效 ID 后，将焦点交给带目标运行 ID 标签的详情区；窄屏同时定位到详情，不要求用户在长列表后自行寻找反馈。只在该次导航成功或重复打开当前记录、完整目标 URL 仍一致且没有更新意图时执行；被取消 / 拒绝的旧导航、外部导航和 Back / Forward 不接管焦点。
- 原布局的固定三行 grid 含一个条件错误区，正常态与错误态依赖不同的隐式排布。本轮改用明确的纵向 flex 分配。小于 `xl` 时页面可纵向滚动、运行列表最高 36rem；`xl` 起保留双栏，列表和详情各自滚动。日志在窄屏为 24rem、`lg` 到 `xl` 为 32rem，`xl` 才使用父区域高度，避免在不定高 grid 内依赖 100% 高度。

这些选择参考了 [W3C 认知可访问性页面结构建议](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o2p03-page-structure/)中关于逻辑分区、标题、相对重要性和相关项分组的原则，以及 [NN/g 渐进展开](https://www.nngroup.com/articles/progressive-disclosure/)中关于清楚区分主要与次要任务、保留易发现入口的建议。它们是设计启发，不能代替实际任务测试，也不证明本产品的认知负荷、效率或转化率已经改善。

## 不变的交互口径

- 名称 / ID 关键词仍只搜索已加载的本页；工作流、状态和分页仍由既有服务端参数处理
- 紧凑统计沿用 `historyRuns`，即名称 / ID 关键词过滤前的本页数据；结果数使用 `visibleRuns`，两者在关键词筛选后可以不同
- 加载或列表失败时，统计显示破折号，不把旧数据或暂缺数据冒充零记录
- 独立 ID 打开仍保留 URL 筛选条件，支持列表以外的详情；分页、前进后退、错误重试和离页恢复沿用原有逻辑
- 中、英、日三种语言均有分组、范围和选中状态文案

## 验证范围

新增十五项回归覆盖统计归属和口径、名称与完整 ID 层级、原生披露元素保留草稿及独立打开、等待 / 迟到详情的选中归属、响应式 class / DOM 结构契约、主动打开后的焦点交接、被阻止或取消的导航、Back / Forward、重复打开、长名称及英日文案。最初五项在原生产基线上全部失败；新增焦点行为的三项在实现前失败，独立复核发现的“已取消导航遇到同 ID 的新路由”与回退反例也分别先失败、修复后通过。两处既有列表测试只将 ID 提取 helper 改为专门的 ID 标记，未改变预期列表或削弱原断言，并补强加载 / 失败统计和空结果语义断言。

相关 Vue、Pinia、Vue Router memory history、页面、API 映射和组件测试，以及强制类型检查和生产构建提供前端结构与逻辑证据。HTTP、实时传输和部分旁支组件使用受控替身。焦点断言使用附着于 jsdom document 的实际元素；`matchMedia` 和 `scrollIntoView` 在相关用例中受控替换，证明调用条件和目标，不证明真实滚动位置。滚动相关回归只验证结构和生成 CSS，不是像素验收。

### 状态与交互验收清单

- 当前位置与下一步：运行记录 / 本页匹配 / 所选详情有清楚分组；名称、完整 ID、状态、选中文字与路由一致
- 主要与独立任务：筛选直接可见，按完整 ID 打开有明确披露标题；收起 / 重开不丢草稿，输入无效不导航
- 等待：列表隐藏旧筛选结果，统计为破折号；目标详情等待不会重新显示旧审批，详情区有 busy 状态
- 空结果：区分本页关键词无匹配、服务端筛选无结果及页码超出范围；空态有 status 语义，过期页提供返回第一页
- 失败与恢复：列表失败仍能查看独立深链，显式重试恢复该页，保留筛选与当前详情；原有取消 / 审批失败和重复操作回归继续运行
- 操作反馈：主动打开后的 DOM 焦点到对应详情；窄屏有定位调用，宽屏不调用页面定位
- 中断与重复：被拒绝导航不挪焦点，较新选择 / 外部同 ID 导航 / Back / Forward 不被旧回调接管；再次打开当前记录不重复读取列表
- 信息边界：关键词过滤前统计与关键词匹配数明确区分，列表以外详情有说明；长名称及中英日分组文案有回归
- 键盘与响应式：已验证可聚焦区域、原生 disclosure 结构和 CSS 高度 / 溢出契约；原生 Tab / Enter / Space、屏幕阅读器和各尺寸真实滚动仍待浏览器验收

本轮曾启动全量前端测试，随后按范围要求终止，退出码为 130，不能算作全量通过；日志没有逐项完成信息，无法据此确定终止前执行过哪些用例。最终验收仅使用运行页和直接相关时间线 / 日志组件的有界回归，不扩展到身份、租户、安全或图安全集合。

最终结果：选定范围 15 个测试文件、151 / 151 项通过；`vue-tsc -b --force`、Vite 生产构建及九项生成 CSS / 断点规则检查通过。构建保留既有大于 500 kB 分块提示。早先执行的十四组既有静态契约检查全部通过，没有真实服务探测；后续焦点变更后未重跑无关集合，不把它们称作全量验收。依赖未安装或升级，原始用户工作区的受跟踪文件、索引及暂存状态校验一致。

未进行真实浏览器的 320 / 768 / 1024 / 1280px、短屏、缩放、原生键盘与屏幕阅读器验收，也没有真实后端、数据库、Provider、Java 全量、部署或容量验收。现有 CI 仅监听 `main`，面向维护分支没有检查不能算作 CI 通过。

建议在可用真实浏览器中重点检查：长名称与日文文案；加载 / 失败提示存在和不存在；多条节点输出与长日志；展开 / 关闭 ID 入口后继续筛选；列表外深链及 Back / Forward；窄屏滚动至详情与宽屏独立滚动。
